- An isolation or allowlist check over a config format (compose, k8s, CI) must enumerate every field of that format that reaches outside resources, with one test each, not only the field with the obvious name: compose reaches host data via `type: bind`, `driver_opts.device` on a named volume, `volumes_from: container:`, `configs`/`secrets` with a `file:` source, and `extra_hosts` mapping to `host-gateway`. The enumeration covers both axes, not only runtime: when the tool also builds images (the lab keeps `build:` and runs `up`, so it builds on the host daemon), `build.ssh`, `build.additional_contexts` with a host path, and a `build.context` outside the project tree read host files at build time and must be checked too. Missing the whole build-time axis passed review once (PR #21).
- Commits, PR descriptions, docs and file names never name the project a measurement or session came from, nor a third-party tool the maintainers use: a session folder under `~/.claude/projects/` carries the project's path, and copying it as a label leaked a private project name into a commit message. Say "a pilot project" / "a third-party filter". Safe mentions: this repo, license-required attribution (gitleaks), libraries a skill recommends.
- Replacing a gate's whole-line text pattern with a per-command (tokenized) check drops what the pattern matched by accident: the command run as an argument (`find -exec`, `xargs`, `watch`, `flock`), inside a shell's `-c` script, as `eval`'s arguments, and as a string inside an interpreter one-liner (`python3 -c "os.system(...)"`). Before deleting the pattern, add a corpus row for each of those forms, in every gate that used it (code-write, secret, and the git readers: push attribution, push secrets, review, commit), in `tests/unit/test_gate_evasion.py` / `tests/unit/test_secret_scan.py`.
- A new handler that takes over an existing command or entry point (a mod intercepting a skill's slash command) must keep every entry the old one offered reachable: list them from the old handler (the skill's menu screens) before writing the new one, with one test per entry.
- A pane a mod opens says in its own text what it is and how to drive it (keys, how to leave), puts its exit control first with a hotkey, sets `autoFocus`, and is tried live in a session before its PR: `claude plugin test` presses buttons without focus, so it cannot catch a panel the keyboard never reaches.
- An installer that renders values into a target project's files writes nothing machine-specific into a file that project commits (an absolute home path carries the user name and breaks for teammates): write `$HOME/...` or a discovered path, with a test that the rendered file holds no home path.
- A gate change that reads more input (script files, heredocs, a broader pattern) is replayed through the old and new checks over the recorded Bash commands in `~/.claude/projects/*/*.jsonl` before its PR, and the PR states the verdict changes: reading tracked build scripts blocked 184 of 6900 real commands.
- A test that feeds a parser a hand-written sample of an external tool's output (CSV, JSON, report) proves only the parser, never that the tool emits that shape: the sqlmap mode read a `--results-file` CSV that sqlmap 1.10.9 writes only in multi-target mode, so the single `-u` lab run produced none and every scan reported "not injectable" with exit 0 — tests green. A feature that drives an external CLI reads its output contract and exit-code semantics from the tool's own source/docs (sqlmap exits 0 even when it never connected), and ships with one real run of that CLI that reaches the true outcome — a confirmed finding, not just the empty case — through the sanctioned path (opt-in e2e, `PLAYBOOK_LAB_IT=1`).
- A feature whose spec was in a cleared session is not built from the literal reading of its name — confirm the intent while the user is present: "language detect" meant making the playbook speak the user's idioma (localize the `/playbook-config` menu and the replies, and fix the model reverting to English after a `/clear`), not detecting the programming language; "tour" meant a skippable first-run config walkthrough, not a printed `install.sh` line. The SessionStart context is English, so after a `/clear` the model must be told to keep the user's language or it switches to English.
- Writing the opt-in e2e is not running it, and unit tests that mock the orchestrator (`_scan_target`) never exercise the integration under it: the `--gate` feature remapped the build context into a `/tmp` worktree, which `validate_lab_config` then refused as "outside the project", so every gate run aborted before any scan — dead on arrival with the whole unit suite green and an unrun `PLAYBOOK_LAB_IT` e2e that would have caught it. Before claiming a feature works: run the opt-in e2e, or — when its image is too heavy to pull here — run a real-tool check of the exact new sub-path (real `git worktree` + `docker compose config` through `build_lab_config`→`validate_lab_config`), and add a unit test that drives that integration, not one that mocks it away. Caught in review (PR 2b).
- A parser reading a value a config format lets take several textual forms must handle every form, and one it does not recognise must surface as unknown/ambiguous, never silently yield nothing: a compose port is a single `8080`, a range `8000-8005`, a `/tcp` suffix, `host:container`, or long-form `target`, and reading only the single integer dropped a service with a port range as "no port" (empty read downstream as "the field is absent", so the service was skipped). One test per form, and the unhandled form fails loud. Caught in review (PR #22).
- A reader that widens scope by following references (the audit surface: routes → the types they use → their implementations, and back up to referrers) follows only edges that narrow to one owner: an interface to its implementations, never a base class to its subclasses, and never a type declared outside the repository (a framework interface such as `OnInit`). One shared parent (`extends BaseEntity`, `: Base()`, `implements OnDestroy`) links every subclass to every other and pulls the whole codebase in; a test drives a shared base through the expansion and asserts its siblings stay out. Every input the reader could not open (an unlisted folder, an unreadable file) is named under `limits`, never dropped. Caught in review (audit surface PR).
- A skill step that tells the model to run something (a script, a request to the application) is written against the real input and the other skills that govern the same action, not against the common case: its arguments are the ones the hook or script actually computes, edge included (the push range of a branch with no upstream falls back to the default branch, so `--diff <upstream>` had no base on a first push), and before its PR every other skill that rules the same action is read for a conflict (the audit's "send requests to the local app" collided with `engineering-security`'s lab-only rule for crafted requests), with the tie-break written in the new step and a structural test that pins it. Caught in review (audit mode PR).
- A gate that decides by a write's destination takes the destinations from every channel a write can take, not only the editing tools: Write/Edit/MultiEdit, a shell redirect or `tee` (`cat > Dockerfile <<EOF`), and the copy/move/download commands `bash_write_targets` reads. The topic rows of the skill gate first read the editing tools' path for any file but the shell only for source extensions, so a Dockerfile written from the shell skipped `engineering-docker`. One test per channel, and a channel left uncovered is named in the code. Caught in review (skill requirement gate PR).
- Replacing a rule the skills repeat means finding every restatement of it by meaning, not by the old wording: the decision-ownership change swept the literal "stop and confirm" / "When ambiguous: stop" out of every skill, and the same rule survived reworded as "mark it explicitly and ask before acting on it" in `engineering-playbook` and "state it and ask before acting" in the Antigravity template, still contradicting the new rule. Before the PR, grep the rule's verbs and synonyms (ask, confirm, wait, stop) across `skills/`, `adapters/`, the hook texts and `docs/templates/`, and add each retired phrasing to the structural test that forbids it. Caught in review (decision ownership PR). A pointer to a rule names the rule and does not summarise its content: the implement checklist's pointer listed the two obligations rows that existed when it was written and went stale when two more were added in the next commit. Caught in review (obligations PRs).
- A gate that lets a command through on something other than the command text (a literal it resolves, an approval it stores) lists, before the code, every way the model or the shell can change that something between the check and the run, with one evasion-corpus row each: for a resolved shell variable, word splitting (`IFS`), every construct that runs code conditionally or later (`&&`/`||`, `if`/`case`/loops, `{ }`, subshells, `function` bodies) and every statement that rebinds in the current shell (`source`, `.`, `eval`, `read`, `for`); for a stored approval, the model writing the store itself (deny calls naming it) and an approval reaching something the user never saw (only what a finished turn listed). Missing `IFS`, `function` and the self-written store passed the first draft. Caught in review (auto-mode consent PR).
- A value a gate carries to show the user (the destroying part in a dialog) belongs to the text it was read from: a check that recurses into other text (a script file, an interpreter one-liner) returns lines of that text, and the outer caller must map them to the command the user is asked about or drop them, never pass them on as part of it. The first draft showed a script's `rm -rf dist` as "one part of" a `cd x && ./clean.sh` it does not appear in. One test per recursion channel asserting what is shown. Caught in review (rm tokens PR).
- Text that a party other than the person writes (the model through a script, a command's output, a file) and that a mod draws beside a control the person presses is checked for control characters where it is stored, with a test per field: the terminal runs an escape sequence, so a `--what` holding one could redraw what the person reads before pressing Remove, and what they approve must be exactly what runs. The same review found the matching limit on the other side: checks a mod's call makes on external tools (`docker inspect` per item) share one time budget under the call's own limit. Caught in review (Temporary data registration PR).
