# Red-playbook — plan

Status: approved 2026-11-16. One branch per phase. This file is the hand-off
between sessions: update the status line of a phase when it lands.

## Principle

The playbook is a governance plugin, so it ships **defense**. The proof that a
defense holds is an **attack**, run against two targets only, both local:

1. **The playbook itself** — attempts to get past its own gates, run as unit tests.
2. **The user's application running locally** — an optional Docker lab whose
   scanner can only reach the containers of that lab.

The attack is kept at the level the proof needs: the hostile input and the path
it takes to a dangerous sink. Exploitation chains, evasion of detection and
post-exploitation stay out. Nothing published (production, staging, any host
outside the lab) is ever a target, and there is no override for that.

No new skills: everything below completes skills and hooks that already exist.

## Phase 1 — native secret scanner

Status: merged in #66 (branch `feat/red-playbook-secret-scan`, 2026-11-16). 110 deny / 98 warn / 14 off rules. Hook latency measured at
50-90 ms per call including Python start-up. PreToolUse timeout raised from
10 s to 20 s: a push now runs the attribution log, the secret log (4 s cap)
and the review gate. Known gaps: Codex `ApplyPatch` is not read at write time
(its input format is unverified; commit and push still cover it), untracked
files added in the same command as `git commit` are seen only at push, and the
push scan reads `git log -p`, which shows no diff for merge commits (a value
introduced while resolving a merge conflict is not seen).

- `hooks/secret_scan.py`: rule loading, scanning, and the checks the hooks call.
  Shared by the Claude Code and Codex guards.
- `hooks/data/secret_rules.json`: generated by `scripts/sync_secret_rules.py`
  from the pinned gitleaks file. The runtime reads only the JSON.
- Tiers, computed by the sync script from the rule's shape:
  - **deny**: rules with a distinctive token shape (`AKIA`, `ghp_`, `glpat-`,
    `sk_live_`, `xox`, private-key header...).
  - **warn**: keyword-anchored rules, plus `generic-api-key`, `jwt` and other
    shapes common in fixtures.
  - **off**: client ids and public keys, which are not secrets.
- Check points:
  - Write / Edit / MultiEdit / NotebookEdit: only lines the call adds; skipped
    when the target is outside the repository or git-ignored (a secret in an
    ignored `.env` is the correct practice).
  - Bash that writes a file: the command text, deny tier.
  - `git commit`: added lines of the staged diff (the `HEAD` diff with `-a`).
    Fails open: the push check is the backstop.
  - `git push`: patches of the commits no remote has. Fails closed.
- Exceptions belong to the user only: `.playbook/secrets-allow`, one
  fingerprint per line. The hook denies the model writing that file. Inline
  `gitleaks:allow` markers are not honored, because the model could write them.
- A deny message never contains the secret, only a redacted prefix and the
  fingerprint.
- `scrub_secrets` (failure journal) also redacts deny-tier matches.

## Phase 2 — evasion corpus for the playbook's own gates

Status: merged in #68 (branch `feat/red-playbook-gate-evasion`, 2026-11-16). Baseline measured with the gates as they were: 19 of 30
destructive attempts and 13 of 16 code-write attempts passed; all of them are
now caught. The corpus holds 71 destructive rows (50 must block, 21 must pass)
and 31 code-write rows (23 must gate, 8 must pass), plus 4 known gaps.

Replayed against 5085 real Bash commands from 26 transcripts. That replay found
two bugs the corpus did not: `strip_heredoc_bodies` left every heredoc after
the first with the same delimiter unstripped (a pre-existing source of
destructive false positives, now fixed), and `$(...)` split commands at its
parentheses. What still changes verdict on real commands, all by policy:
`$P "select ..."` (program in a variable, 5 commands), `git stash drop`,
`git restore <path>`, and copies, moves and `git checkout -- <path>` of source
files now arming the code-write gates.

Left open on purpose (each one is a row in `KNOWN_GAPS`): heredoc scripts are
not read for deletion APIs or write targets, a script file's content is not
read, and recursion passed through a variable is invisible. Codex: not
installed on this machine, so the `_emit('deny')` question is still open.

- `tests/unit/test_gate_evasion.py` with every attempt and its expected verdict.
- `check_destructive`:
  - normalization: unquote the command word, drop git global options (`-C`,
    `-c`, `--no-pager`, `--git-dir`, `--work-tree`) before matching;
  - missing patterns: `git stash clear|drop`, `git reflog expire`,
    `git update-ref -d`, `git filter-branch`, `git branch --delete --force`,
    `git restore <path>` (not `--staged`), `rsync --delete`, `shred`,
    `truncate -s 0`;
  - not attestable: command word from a variable or a substitution, and
    `-c`/`-e` interpreter payloads calling destructive APIs (`rmtree`,
    `rmSync`, `unlink`, `os.remove`) — blocked with the same user
    authorization flow as `rm -rf` (decision 2026-11-16).
- `is_code_write`: target extraction for `cp`, `mv`, `install`, `ln`,
  `dd of=`, `curl -o`, `perl -i`, `awk -i inplace`; `git apply`, `patch`,
  `git checkout <ref> -- <path>` and interpreter writes count as code writes
  when the target cannot be resolved.
- Attribution gate cases: `git -c ... commit`, `-F` with a generated file,
  `commit-tree`.
- Codex adapter: `_emit('deny', ...)` writes only `{"continue": true}`; verify
  whether a deny actually stops the call on the installed Codex.

- **3a — knowledge** (branch `feat/red-playbook-defensive-knowledge`,
  2026-11-16): the 13 fiches, `engineering-security` 2.3.0 (fiche index, WAF
  and proxy notes; the lab section waits for phase 4), `engineering-testing`
  2.2.0, `engineering-code-review` 4.0.0, `engineering-docker` 2.2.0, the
  Antigravity adapter copying `references/`, and structural tests that keep
  the index, the fiche sections and the review output format in sync.
- **3b — tooling** (branch `feat/red-playbook-sast-and-fixtures`,
  2026-11-16):
  - **SAST delegation.** Detected at SessionStart and handed to the model as
    a validation step, with the exact command. Not run by the hook: a scan
    takes seconds, the Stop hook has 10 s, and a timeout fails open. This
    changes the mechanism from the original "in the validation gate"; the
    policy is the same (`--metrics=off`, failures open, block on ERROR).
    Findings above ERROR are not filtered by confidence, because the CLI has
    no flag for it.
  - **Fixtures.** 13 behavioral review fixtures (06–18), one per fiche, with
    "Must mention" checks. The runner now runs every prompt file and no longer
    exits on the first `((PASS++))` under `set -e`.
  - **Review gate fix.** It no longer blocks a push that only deletes refs.

- `skills/engineering-security/references/`, loaded only when code reaches the
  sink: injection, xss, redirects-and-headers, ssrf, files, untrusted-parsing,
  access-control, tokens-sessions, business-logic, graphql, crypto,
  supply-chain, llm-apps.
- Fiche format: invariant, sinks, control, negative proof (hostile input set
  for a test), dynamic proof (lab check), review signal, CWE.
- `engineering-security` MINOR: fiche index, lab section, "a WAF is not a
  control", proxy normalization note.
- `engineering-testing` MINOR: every security control ships with a negative
  test using the fiche's hostile inputs.
- `engineering-code-review` **4.0.0** (output format changes, decision
  2026-11-16): closure states confirmed / ruled out (named control at
  file:line) / open proof gap; diff scope (newly reaches, weakens a guard,
  removes a control); Blocker carries CWE and trace.
- `engineering-docker` MINOR: read-only filesystem, `cap_drop: ALL`,
  `no-new-privileges`, Docker socket never mounted.
- semgrep / opengrep when installed, in the validation gate: `--metrics=off`,
  fail open on errors, block only ERROR + HIGH confidence.
- Behavioral fixtures: one intentionally vulnerable snippet per class in
  `tests/behavioral/prompts/`.

## Phase 4 — local validation lab

Status: merged in #71 (branch `feat/red-playbook-lab`, 2026-11-16). Changes from
the design below, all agreed with the user:

- **Rendered file instead of an overlay.** The lab renders a complete compose
  file from the project's resolved configuration and runs it as its own
  project. It drops ports, `container_name`, network and volume `name`, and
  the `image` tag of built services. This keeps it off the developer's
  stack. Real Compose re-derives every name under the lab project
  (`redlab-<dir>_pgdata`); checked against Compose v5.6.1.
- **Nothing kept.** The report lives in a temporary directory and is deleted
  after printing. `down -v --rmi local` runs in a `finally`. Only the image
  stays cached; `--setup` states its size and `--uninstall` removes it.
- **Setup and pull.** `--setup` checks Docker, daemon permissions, Compose
  version and disk space, then pulls by digest on the user's machine. The
  playbook ships no image.
- **Bind mounts.** Refused by default, with the list; `--allow-bind-mounts`
  overrides.
- **Tests.** The end-to-end test is opt-in (`PLAYBOOK_LAB_IT=1`) because it
  needs the ZAP image (3.75 GB on disk). Run on 2026-11-16: both tests pass
  (bind mount refused before start; scan reports and leaves no container,
  network or volume). The first run hung because the fixture served `/` and the
  spider walked `/proc`; the fixture now serves its own directory and the scan
  has a total time bound.
- **Hook gaps.** A renamed scanner binary and hand-made hostile `curl`
  requests are not recognized (`KNOWN_GAPS`).

- `lab/compose.lab.yml` (overlay on the project compose) and `lab/run.py`.
- Network `redlab` is `internal: true`; the scanner is attached to it only.
- `run.py` validates the effective config (`docker compose config`) before
  starting: scanner only on `redlab`, `redlab` internal, no `network_mode: host`,
  no `privileged`, no Docker socket mount.
- Target allowlist: `http://<service of the compose>:<port>` only. Anything
  else, including the project's published domain, is refused.
- v1 scanner: OWASP ZAP baseline (passive), official image pinned by digest.
- The app must run in the compose (decision 2026-11-16).
- ZAP JSON report converted to the finding format; each finding becomes a
  negative test.
- Hook: deny scanner binaries and images outside `run.py`, and deny
  `--network host`, `--privileged` or a Docker socket mount on them.

## Phase 5 — native output filter

Status: merged in #72 (branch `feat/red-playbook-output-filter`, 2026-11-16). Premise
verified 2026-11-16 on Claude Code 2.1.325: the PostToolUse
`updatedToolOutput` field "works for all tools", and an output that does not
match the tool's output shape is discarded in favor of the original. Hooks run
in parallel on the original output and the last rewrite wins, so only one
output filter may be active.

Measured 2026-11-16 with a probe hook in `claude -p` sessions, before design:

- A rewrite reaches the model for Bash and for Read.
- Bash caps `stdout` at 30,000 characters before any hook sees it. Above that,
  Claude Code saves the full output to a file (`persistedOutputPath`) and the
  model sees only a short preview; a rewrite of such an output is ignored.
- Recomputed against that cap, the usage history of the third-party filter
  the author ran before (39,259 commands) saved 3.3 M tokens of the 13.3 M
  the model would have seen (25 %), not the 94.8 M (87.9 %) that tool
  reports. Its biggest claim, `cat` of multi-MB logs
  (88 M), is 1.7 M real: Claude Code already cut those to a preview. The real
  saving is in mid-size outputs: `cat` 1.7 M, `grep` 0.84 M, `ls` 0.53 M,
  then `git log`, `ruff`, test runners and linters far below.

Decisions (user, 2026-11-16):

- PostToolUse filter, Bash only: the command runs unchanged, so no
  permission-rule interplay and the exit status untouched. stderr is never
  changed. A filter error passes the original through.
- Skipped: output already persisted by Claude Code, interrupted, image, under
  1,000 characters, or less than 10 % shorter after filtering. Never larger.
- Recovery without disk: no raw file is kept. A filtered output ends with a
  `[playbook:filter]` line; re-running the command with `PLAYBOOK_RAW=1` in
  front returns it unfiltered. Only read-only commands are filtered, so a
  re-run is safe.
- The Read tool is not filtered: the model builds Edit's `old_string` from
  what Read returned, and altered content breaks the edit.
- Ledger in the session only, shown by `/playbook-config`; the
  baseline is what the model would have seen.
- Port order, by measured real saving: `grep`/`rg` grouped by file, `ls -la`
  compacted, `cat` of a non-code file with repeated lines collapsed (a code
  file passes untouched), `git log`, test runners failures-only, linters
  grouped.

Built: `grep`/`rg`/`git grep`, `ls -l`, plain `git log`, and the ledger
(`output_filter.py --report`, shown by `/playbook-config`). On this
repo: grep 25,597 -> 14,319 chars, `ls -la` of two directories 1,763 ->
1,357, `git log -n 15` 15,362 -> 5,748.

Dropped after measuring, pending the user's agreement:

- `cat`. Of its 1.7 M "real" saving in that history, 81 % comes from outputs
  under a tenth of their input: plain `cat <file>` of a 7,500-token source file
  that came back as 4 to 106 tokens. The model did not get the file, which is
  not a saving. Without that, there is no evidence a `cat`
  filter helps, and a source file must reach the model as written.
- Test runners and linters. Together (ruff, prettier, vitest, eslint) about
  95 k of the 3.3 M real tokens (3 %), each with its own format, and a
  filter that drops a failure's detail costs more than it saves.
- Cut-over: the previous tool's hook, its `CLAUDE.md` include, binary,
  configuration and data were removed from the author's machine on
  2026-11-16; its history database is kept as
  `POC/token-measure/filter-history.db` (gitignored). The filter does not
  detect other tools: output another tool reshaped matches no rule and
  passes through. It starts with the next session, since hooks are read
  when a session starts.
- Codex adapter stays pass-through until verified on the installed Codex.
